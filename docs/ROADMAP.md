# Roadmap

This document describes possible future work. It does not promise that the features below already exist.

## Near-term product work

1. **A stronger mission overview.** Bring unresolved issues, pending reviews, and key changes for all four profiles into one concise summary.
2. **Durable simulation archives.** Preserve completed runs with their scenarios, events, notes, and configuration. Add replay without mixing current and past data.
3. **Richer demonstration history.** Introduce explicit versioning, corrections, and review states for fictional records. Distinguish missing information from known-negative findings.
4. **Structured handovers.** Extend existing report tools with individual case timelines and clearly identified unresolved questions.
5. **Scenario event controls.** Trigger or schedule controlled changes and annotate why they were introduced.

## Evaluation and technical work

- Review the interface with intended users and measure comprehension and task completion.
- Test keyboard navigation, screen readers, small screens, and representative WebGL devices.
- Profile the application at the fastest simulation speed and optimize expensive updates.
- Separate a future device-adapter interface from synthetic data generation.
- Introduce versioned scenario fixtures and reproducible evaluation reports.

## Before any operational use

Operational use would require domain-specific requirements, professional medical review, data governance, security and access controls, a defined human-review process, suitable validation data, and independent evaluation. The current prototype is not evidence that those requirements have been met.

## Deliberate boundaries

The immediate aim is a clear, explainable monitoring and follow-up experience. An autonomous diagnosis engine, medication advice, real personal medical records, and claims of NASA certification are outside the demonstrated scope.
